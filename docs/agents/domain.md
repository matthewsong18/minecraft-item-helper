# Domain docs

This repository uses one root GLOSSARY.md and docs/adr/ for
architecture decisions.

Before exploring the codebase:
- Read GLOSSARY.md.
- Read ADRs relevant to the work.
- Proceed silently when either is absent.

Use the glossary's terms in specs, tickets, code, and tests.
Surface conflicts with existing ADRs explicitly.
Create glossary entries and ADRs when terms or decisions are resolved.
